## 6. Cloud storage abstraction — scaffold only (deployment steps 4–5)

**What.** A typed, non-wired skeleton for the cloud storage seam: a
sqlite3-compatible facade over Cloudflare **D1**, an **R2** object store, and a
note-content store with a local-persist vs cloud-client-offload split.

**Why.** Running server-side breaks three local-first assumptions (shared-secret
auth, persistent local FS + single-instance SQLite, in-process workers). Auth
and workers are handled (change-set 5); this file pins down the *storage* shape
before spending real Cloudflare integration effort. Records the key correction
that **D1 is SQLite, not MySQL**, so the existing SQL/schema/migrations port

## 5. Deployment mode toggle + per-user bearer-token API + mode-aware auth + fast boot

**What.** Added `CEREBRUM_DEPLOYMENT_MODE=local|cloud` (default `local`). Login
now mints a signed bearer token; the auth middleware is mode-aware; cold boot no
longer blocks on the manifest scrape and in-process workers only run locally.

**Why.** To host the daemon on Leapcell (serverless, multi-tenant): the single
shared `X-Daemon-Key` is meaningless across real users, `X-User-Id` was
trust-the-header, awaiting the manifest scrape at startup risked Leapcell's ~10s
boot budget, and the background drain loops silently stall when a serverless
process is frozen. This is the "user API" to reach the daemon.

**Files.**
- `cerebrum_core/deploy_config_inator.py` — NEW: `deployment_mode()`/`is_cloud()`/`is_local()`, `TOKEN_MAX_AGE_SECONDS`. Imports nothing from `api` (keeps layering one-way).
- `api/auth/token_inator.py` — NEW: `mint_token`/`read_token` via **itsdangerous** (already installed; no new dep). Secret = `CEREBRUM_TOKEN_SECRET` (required + shared across instances in cloud) else the daemon key file (local).
- `cerebrum_core/middleware/daemon_auth_middleware.py` — rewritten mode-aware: local = `X-Daemon-Key` gate + `X-User-Id` identity; cloud = mandatory `Authorization: Bearer` (header identity ignored). Resolves a bearer token to `request.state.user_id` in either mode. `PUBLIC_PATHS` now also lets `POST /user/account` and `/user/login` through unauthenticated.
- `cerebrum_core/utils/user_context_inator.py` — `get_current_user_id` prefers `request.state.user_id` (middleware-verified token), else `X-User-Id` (local).
- `api/routes_user.py` — `/user/login` returns `token`.
- `cerebrum_inator.py` — manifest scrape fired as a background task instead of awaited; grading/generation/file-queue workers gated to `is_local()`; tasks cancelled on shutdown.

**Verified.** Token mint/verify/expiry/tamper roundtrip; cloud-without-secret raises. Full TestClient run of both modes against a stub repo: local (no-key→401, key+`X-User-Id`→OK, key+token→OK); cloud (no-token→401, header-alone→401, valid-token→OK, bad-token→401).

## 3. Discretionary per-file access scoping (shared pool, opt-in private)

**What.** A `file_access` table on the file registry: a file with no rows is
public/pooled (default), one+ rows makes it private to the listed users/orgs.
Single enforcement point `filter_visible(...)`, wired into file listing + search.

**Why.** Files are intentionally a shared pool, but users/orgs need optional
separation of which files serve whose learning goals — without touching chunk or
vector metadata. Enforcement lives entirely at the registry layer.

**Files.**
- `database/file_registry_inator.py` — `file_access(file_fingerprint, principal_type, principal_id)` table; `grant_access`/`revoke_access`/`list_access`; `filter_visible(fingerprints, user_id, org_ids)` (public = no grants); `show_all_inator` gains optional principal filtering; `remove_inator` drops a file's grants (no cross-DB FK).
- `api/routes_knowledgebase.py` — `/show` filters to visible files; `/search` post-filters vector hits by `metadata.file_fingerprint` (fail-closed when absent); NEW `GET/POST/DELETE /knowledgebase/access/{fingerprint}` (can only share a file you can see; org grants require membership). Added `Depends(get_current_user_id)`.

**Verified.** Temp-DB: no-grants→all public; user grant private-to-user; org grant visible to members not others; list/revoke→public again.

## 2. User account routes: ownership fix (identity, not path param)

**What.** `GET`/`DELETE /user/account/{user_id}` → `GET`/`DELETE /user/account`,
deriving the user from identity.

**Why.** Taking the target id from the path with no ownership check let anyone
with the daemon key read or wipe any account by id. Identity-derived means you
can only ever touch your own account.

**Files.**
- `api/routes_user.py` — dropped the `{user_id}` path param on get/delete account; both now use `Depends(get_current_user_id)`; imported `Depends` + `get_current_user_id`.

**Verified.** Router registers `/user/account` (no path id); import check.

## 1. Registered daemon-key middleware + credential-backed accounts (email + bcrypt password + login)

**What.** Actually mounted the (previously unregistered) daemon-auth middleware,
and made accounts credential-backed: mandatory unique email + bcrypt password,
with a `/user/login` endpoint.

**Why.** `DaemonAuthMiddleware` existed but was never added to the app — every
route was open despite the key being printed at boot. And the `users` table had
no password at all (the `User` model's `password` field was vestigial), while
`create_account` let `email` be null despite the column being `NOT NULL UNIQUE`.

**Files.**
- `cerebrum_inator.py` — imported + `add_middleware(DaemonAuthMiddleware)` inside the CORS layer (so preflight/401s still carry CORS headers). CORS `allow_origins=["*"]` left as-is (fine for a native client; the daemon key is the real gate).
- `cerebrum_core/middleware/daemon_auth_middleware.py` — added `/` to `PUBLIC_PATHS` and an `OPTIONS` bypass (later superseded by change-set 5's mode-aware rewrite).
- `database/note_engram_repository/schema.py` — `users.password_hash TEXT NOT NULL DEFAULT ''`.
- `database/note_engram_repository/migrations.py` — migration `0003_add_user_password_hash` (guarded ALTER for existing DBs; legacy rows get a blank hash that no login matches).
- `api/auth/password_inator.py` — NEW: bcrypt `hash_password`/`verify_password`, explicit 72-byte cap.
- `database/note_engram_repository/users.py` — `create_user` takes `password_hash`; NEW `get_user_by_email`.
- `api/routes_user.py` — `AccountCreateRequest` requires `email` + `password` (min 8); NEW `POST /user/login` (verifies against a blank hash even when the email is unknown, to not leak which emails exist).

**Verified.** bcrypt roundtrip + long-password rejection; migration `0003` on a simulated pre-column DB (fresh has it; legacy row blank → cannot log in); signup + login roundtrip.
