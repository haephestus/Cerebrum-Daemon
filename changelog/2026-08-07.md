## 1. Group codebase by utility — hoist infra to top-level packages; `cerebrum_core` becomes domain-only

**What.** Moved every infrastructure concern out of `cerebrum_core/` up to
top-level packages (siblings of `api/`), and dissolved the `cerebrum_core/utils/`
grab-bag by role. New top level: `api/  agents/  cerebrum_core/  vectorstore/
database/  storage/  notes/  common/  models/`. `cerebrum_core/utils/` no longer
exists.

**Why.** `cerebrum_core` mixed domain logic (engrams, planners, knowledgebase)
with infrastructure (database, storage), and `utils/` was an 18-file junk drawer
holding the vector stack, the note pipeline, and pure cross-cutting helpers all
together — including *two* separate vector-store stacks. Grouping by utility
establishes a one-way dependency rule (`api → cerebrum_core → {vectorstore,
database, storage, models}`; infra must not import domain) and gives the upcoming
note-bundle + D1/R2 + chunk-registry work clean homes.

**Files.** (moves preserve git history via `git mv`)
- `vectorstore/` — NEW top-level package. Moved from `cerebrum_core/utils/`: `faiss_store_inator`, `vector_store_inator`, `embedd_inator`, `embeddings_inator`, `retrieve_inator`. `__init__.py` documents the "must not import cerebrum_core" rule.
- `database/` — hoisted from `cerebrum_core/database/` to top level: all registries (`file_registry`, `file_chunk_registry`, `note_chunk_registry`, `concept_index`, `figure_registry`), plus `note_engram_repository/` and `planner/` subpackages and `migrate_add_note_owner`.
- `storage/` — hoisted from `cerebrum_core/storage/`: `cloud_storage_inator` (the R2/D1 scaffold).
- `notes/` — NEW top-level package: the note ingestion/processing pipeline moved from `cerebrum_core/utils/`: `note_util_inator`, `markdown_handler_inator`, `chunk_analyser_inator`, `chunking_queue_inator`.
- `common/` — NEW top-level package for cross-cutting utils moved from `cerebrum_core/utils/`: `cache_inator`, `file_util_inator`, `archive_inator`, `progress_bar`, `resync_inator`, `ollama_compat/`; plus `deploy_config_inator` moved from `cerebrum_core/`.
- `models/` — NEW top-level package: `model_inator` (LLM adapter) moved from `cerebrum_core/`.
- `cerebrum_core/` — now domain-only: `engrams/`, `knowledgebase_inator`, `learning_center_inator`, `study_planner_inator`, `user_inator`, `constants`, plus `topic_inator` + `user_context_inator` pulled up out of the old `utils/` (they're domain: mastery topics + learning persona).
- `api/middleware/` — `daemon_auth_middleware` moved in from `cerebrum_core/middleware/` (it's HTTP-layer).
- Import paths rewritten across all ~90 source modules + `cerebrum_inator.py`/`nuke_archive.py`. Fixed 5 **over-climbing relative imports** in `database/note_engram_repository/` (`from ...engrams.core…`, which used to resolve into `cerebrum_core.engrams` and now escaped the top level) to absolute `from cerebrum_core.engrams…`. Corrected a stale module-path docstring in `api/auth/daemon_auth_inator.py`.
