## 1. Fix concurrent-write corruption of note manifests

**What.** Note file writes now use a **unique** temp file per writer (was a shared
`<name>.tmp`), and the note-manifest / page-content reads **degrade gracefully**
on a corrupt file instead of crashing the request.

**Why.** Opening a bubble crashed with `json.JSONDecodeError: Extra data` while
listing notes. Two code paths write the same `notes/<id>/manifest.json` —
`_save_note` (client sync) and `write_note_overview` (analysis pipeline) — and both
went through one shared `manifest.json.tmp`. When they raced (exactly what opening
a bubble triggers: analysis runs while the note syncs), they truncated and wrote
the *same* temp; the shorter payload overwrote the head while the longer one's tail
survived, and the atomic `os.replace` could move that mixed file into place → a
complete JSON object followed by leftover bytes ("Extra data"), which bricked the
whole bubble listing (one bad note took every note down with it).

**Files.**
- `notes/note_util_inator.py`
  - `_atomic_write_text` — unique temp via `tempfile.mkstemp` in the target dir + `flush`/`fsync` + atomic `os.replace`, with cleanup on failure. Each writer gets a private temp, so `os.replace` always moves a whole, well-formed file.
  - `_load_note` — note manifest read now goes through `_safe_read_json` and degrades a corrupt manifest to `{}`; page content is the source of truth in the page folders, so `_ordered_page_ids` rebuilds the note from disk and it still loads (title/overview blank until the next save rewrites clean).
  - `_load_page_folder` — page `content.json` / `manifest.json` reads likewise degrade to defaults rather than 500.
  - added `import tempfile`.

**Verified.** Concurrency repro (8 writers × 4 readers on one file): the **old**
shared-`.tmp` writer produced **575** corrupt reads; the **new** unique-`mkstemp`
writer produced **0**. Module `ast.parse` OK. (A full runtime import here trips an
unrelated `pymupdf`/`libstdc++.so.6` native-load outside the nix devshell — not
related to this change.)

**Note.** Fix stops corruption; `_save_note` and `write_note_overview` still do
independent read-modify-write of the manifest, so a rare concurrent overwrite can
drop a just-merged `overview` (lost update, not corruption) — a per-note write lock
would close that if wanted. The already-corrupted note on disk self-heals on its
next save.
