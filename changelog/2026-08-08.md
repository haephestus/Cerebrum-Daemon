## 5. Notes — gap 1 streams B (per-page model) + C (offline-sync backend core)

**What.** The per-page note model + the version-vector offline-sync engine — the
two pieces that had to be settled before any schema froze. Pages now exist and
version (with per-replica clocks); the merge engine + local sync bookkeeping +
the hub-side push are built and tested. The transport protocol + the Flutter
client's half are deferred (they need the other end to exercise).

**Why (B).** Offline-first, multi-device notes can't ride a single monotonic
`content_version` (two offline devices both bump it → collision). Pages are the
unit of sync/analysis; each carries a version vector `{replica_id: counter}` so
"newer" and "concurrent" are distinguishable. Baking the vector into the schema
now means turning real sync on later needs no migration. **Key finding:** pages
already persist through the existing `content.json` store (pages is just a
NoteStorage field), so the per-page *folder* restructure is a sync-granularity
optimisation, deferred to where it pays off (with the protocol), not done
speculatively.

**Why (C).** The merge engine is the correctness heart: version vectors decide
newer-vs-concurrent; genuine conflicts fall back to last-writer-wins **per page**;
ink merges by **stroke-id union** (a delete/tombstone on either side propagates).

**Files.**
- `models/model_inator.py` — `NoteMetadata.version_vector`; NEW `PageMetadata` (+vector) and `Page` (id, index, document, ink, history, metadata); `NoteStorage.pages` (empty on legacy → back-compat). `notes/note_util_inator.note_pages(note)` views any note as pages (synthesising one from legacy content/ink).
- `notes/sync_merge_inator.py` — NEW pure merge engine: `compare_vectors` (equal/dominates/dominated/concurrent), `bump_vector`, `join_vectors`, `merge_ink` (union + tombstone-wins), `merge_page` (LWW-on-concurrent, vector join, ink union, conflict flag), `merge_note` (page-wise).
- `database/sync_store_inator.py` — NEW per-node local bookkeeping (NOT synced): `replica_identity` (stable id = its slot in every vector), `sync_outbox` (offline edits: enqueue/drain/ack), `sync_cursor` (per-peer since-vector — a device talks to >1 hub).
- `notes/sync_service_inator.py` — NEW `sync_push_note(bubble_id, note_id, incoming)` — hub half: merge an incoming replica into the stored note and persist.

**Verified.** Vector comparison incl. the device/PC concurrent case; `merge_page`/`merge_note` (dominates→newer, concurrent→LWW, vectors join, ink unions, conflict flagged); ink tombstone propagation; sync store (replica id stable across re-open, outbox drain/ack, independent per-peer cursors); `sync_push_note` round-trip (first push accepted; concurrent push → LWW merge persisted + conflict reported). Model layer round-trips pages+vectors through the current store; legacy JSON w/o `pages` still deserializes. Full smoke green (107/107).

**Sync transport + client half (added same day).**
- `api/routes_sync.py` — NEW: `POST /sync/push/{bubble}/{note}` (merge incoming into stored via `sync_push_note`, returns merged note + `conflicted_pages` + merged vector), `GET /sync/pull/{bubble}/{note}`, `GET /sync/replica-id`; bubble-owner checked (404 not 403); registered in `cerebrum_inator`. Boot OK, smoke 108/108.
- **Client** (sibling `Cerebrum/` Flutter app): NEW `lib/api/sync_api.dart` (push/pull/replicaId) + `lib/services/sync_service.dart` (stable replica id, per-note version vector, offline **outbox** — all in shared_preferences; `pushNote` bumps our slot → stamps → enqueues → pushes → adopts the server's merged vector; `drainOutbox` retries queued pushes). Wired: `main.dart` drains on startup; `editor_scaffold.dart` routes existing-note saves through `SyncService.pushNote`. Each note merges as one page (the daemon synthesises a page from legacy `content`), so no client multi-page work needed for basic sync.
- **CLIENT DART UNVERIFIED** — no dart/flutter tooling in the build env; needs `flutter analyze`/run. The two new files are additive (can't break the build); the two wiring edits (`main.dart`, `editor_scaffold.dart`) can — verify before relying on them.

**Open.** Pull-since-cursor across notes (needs per-note change tracking); surfacing `conflicted_pages` in the editor UI; true offline note *reading* (needs a client-side note DB — today only shared_preferences); per-page *folder* storage (sync-granularity optimisation). ## 4. Notes — gap 1 stream A: block-aligned chunking + chunk↔block join (+ two bug fixes)

**What.** The note-chunking path now aligns chunks to AppFlowy **block** boundaries
(blocks = stable anchors; chunks = ~512-token retrieval units) and records a
first-class chunk↔block join, replacing size-based splitting with 200-token
overlap. Plus two bug fixes found on the way.

**Why.** The old overlap chunker double-owned blocks (a block landing in the
overlap window appeared in two chunks) and orphaned the tail of any block split
mid-way — so "which blocks does this weak chunk cover?" (for highlighting /
note-analysis / suggested-reading) was ambiguous and incomplete. Block-alignment
makes the mapping exact and both-way queryable.

**Files.**
- `notes/block_chunker_inator.py` — NEW: pure `pack_blocks` (Block/BlockRef/ChunkPlan). Three regimes — pack tiny/normal whole blocks up to the cap; a >cap block splits into pieces all stamped with its id (`is_partial=True`); atomic types (table/code/callout) bypass the cap and stay whole; headings start a fresh chunk; no overlap. Invariant: no chunk mixes part-of-A + part-of-B.
- `database/note_chunk_registry_inator.py` — **fixed a real latent bug**: `_init_table` was creating the *file* `chunks` table (copy-paste) while every method targeted `note_chunks`, so the note chunk path never had its table. Now creates `note_chunks` correctly; added the `note_chunk_blocks` join (+ both-direction indexes) with `register_chunk_blocks` / `blocks_for_chunk` / `chunks_for_block`; fixed `show_all_inator`'s stale column list.
- `notes/note_util_inator.py` — `NoteToMarkdownInator.flatten_blocks` (structured per-block view) + `NoteChunkerInator.chunk_note` (block-aligned; writes the annotated `.md` byte-offset-addressable exactly as before so the analyser's `chunk_fetcher` is unaffected; registers `note_chunks` + `note_chunk_blocks`). `note_processor_inator` switched to it.
- `api/routes_test.py` — `chunking_task` switched to `chunk_note`.
- `cerebrum_core/learning_center_inator.py` — **fixed a second latent bug**: the learning-profile + suggested-reading auto-hooks read `note.user_id`, but `NoteStorage` has no owner field (owner is in the `notes` table). They were silently no-opping; now resolve the owner via `repo.get_note(note_id)["user_id"]`.

**Verified.** `pack_blocks` across the 3 regimes + atomic + heading + the invariant; the registry repair (register → both-direction lookup → embedding progress → idempotent re-register); end-to-end `chunk_note` on a synthetic AppFlowy note — **every chunk reconstructs byte-exactly** from the registry offsets (the analyser's contract), table kept whole, oversized paragraph split into 3 same-id partial chunks, heading packed with its paragraphs. Full smoke green (104/104).

**Not verified here.** Downstream embed (Ollama) + the analysis LLM run — but chunk production, registry rows, and the byte-offset contract the analyser consumes are all verified.

**Open (gap 1, later streams).** B per-page note model (`manifest.json` + `pages/<id>/{content,ink,history,analysis}.json`; the version-vector decision gates its schema), C offline-first sync, D `.cere` bundle + cloud D1/R2. (See memory `note-format-and-chunking`.)

## 3. Password management — authenticated change + forgotten-password email reset

**What.** Two ways to set a password: an authenticated **change** (prove the
current password, set a new one) and an unauthenticated **forgotten-password
reset** via an emailed one-time shortcode → verify → update.

**Why.** Accounts had no way to change or recover a password. Reset is
unauthenticated by nature (the user can't log in), so security rests on an
emailed single-use code + a short-lived signed token, not a session — with
anti-enumeration so the endpoints never reveal whether an email has an account.

**Files.**
- `database/note_engram_repository/users.py` — `update_password(user_id, hash)`.
- `api/routes_user.py` — `POST /user/password` (authenticated change: verifies current, rejects same-as-old / >72-byte, returns a fresh token). Forgotten-password: `POST /user/password/{reset-request,reset-verify,reset-update}`.
- `database/note_engram_repository/schema.py` + `password_reset.py` (NEW mixin) — `password_reset_codes` table (keyed-hashed 6-digit code, 15-min TTL, `attempts` lockout after 5, `used_at` single-use; a new code invalidates the user's prior ones).
- `api/auth/reset_token_inator.py` — NEW: `generate_shortcode` (6-digit), keyed-SHA-256 `hash_code`/`verify_code`, and a signed short-lived reset token (itsdangerous, same secret as `token_inator`, distinct salt) bridging verify→update.
- `api/auth/email_inator.py` — NEW `EmailSender` seam: `DevLogEmailSender` (logs the code — works with no provider) and `ResendEmailSender` (httpx, behind `EMAIL_API_KEY`); `get_email_sender()` picks by config.
- `api/middleware/daemon_auth_middleware.py` — the three reset paths added to `PUBLIC_PATHS`.
- `database/note_engram_repository/__init__.py` — composed `PasswordResetMixin`.

**Flow.** reset-request {email} → always 200; if the account exists, emails the code. reset-verify {email, code} → generic 400 on any failure, counts wrong guesses, returns a reset token on success. reset-update {reset_token, new_password} → validates the token + that the code row is unused/unexpired, sets the password, burns all the user's codes, returns a fresh login token.

**Verified.** Change: new accepted / old rejected / missing-user→False. Reset (with a stub secret): request→verify→update happy path; single-use (burned row rejects replay); 5-attempt lockout; new code invalidates prior; dev-log sender selected when no key. Import smoke green (103/103); boot OK.

**Config / env.** `EMAIL_API_KEY` + `EMAIL_FROM` (absent → dev-log mode, code goes to the log), `RESET_LINK_BASE` (client deep-link the email links to). The `ResendEmailSender` is verifiable only with a real key.

**Open.** Rate-limiting reset-request (per email/IP) to prevent email-bombing — designed for but not added (the daemon has no rate limiter). Token revocation on password change is still out of scope (bearer tokens aren't password-tied).

## 1. Learning profiles — two-layer (declared + inferred), confidence-gated blend, hybrid inference, write-time wiring

**What.** A learner is modelled as a small vector of 4 orthogonal axes
(abstraction↔concrete, breadth↔depth, pattern↔detail, worked-example↔discovery),
each a scalar in [-1, 1]. Two layers are stored SEPARATELY and never overwrite
each other: **declared** (what the user says — the Bayesian prior) and
**inferred** (an append-only evidence log — the evidence). The **effective**
profile blends them confidence-gated: cold start → declared dominates; as
behavioural evidence accumulates the inferred posterior grows and can override.
Inference is **hybrid** — deterministic structural signals now, with a
feature-flagged LLM-enrichment seam for later. Inference is wired **write-time**
at the two points behaviour changes: note analysis, and mastery recompute.

**Why.** Teaching should adapt to the individual (e.g. a pattern-first
"meta-learner" needs detail surfaced so the overall shape holds at the specific
scale). Nothing modelled this before (`user_inator.py` had no learning-style
concept). Two layers kept apart give transparency ("you said X, we observe Y"),
clean re-assertion, and drift audit; weighting toward inferred *but* gated by
evidence avoids both the cold-start problem and ignoring what the user
explicitly asked for.

**Files.**
- `database/note_engram_repository/schema.py` — NEW tables `learning_profile_declared` (prior; one JSON `axes` row/user) and `learning_profile_evidence` (append-only signal log — the inferred posterior is DERIVED from it, no cached-posterior table, so the log is also the growth-trajectory record) + an index. New tables → `CREATE IF NOT EXISTS`, no migration.
- `database/note_engram_repository/learning_profile.py` — NEW `LearningProfileMixin`: get/set declared, add/batch evidence, `replace_evidence_for_ref` (atomic delete+insert per ref → inference is idempotent), read evidence oldest-first.
- `database/note_engram_repository/__init__.py` — composed the mixin onto `NoteEngramRepository`.
- `cerebrum_core/learning_profile_inator.py` — NEW: the `AXES` model, `infer_posterior` (weight-weighted mean + saturating confidence), `effective_profile` (confidence-gated blend with provenance), `render_for_prompt` (persona snippet, near-neutral axes skipped), `sanitize_declared` (clamp + drop-unknown for user input).
- `cerebrum_core/learning_profile_inference_inator.py` — NEW hybrid inference: structural note-analysis mapper (`concept_map.confused_links` → pattern-over-detail / breadth-over-depth), structural engram-performance mapper (relative leans across topic-mastery factual/applied/conceptual/doctoral → abstraction/pattern/depth), `llm_enrich_note_analysis` seam (`LLM_ENRICH_ENABLED`, off), and idempotent drivers `apply_note_analysis` / `apply_engram_performance`.
- `cerebrum_core/user_context_inator.py` — `build_effective_profile(repo, user_id)` — the single generation-time hook returning effective axes + persona.
- `api/routes_user.py` — `GET /user/learning-profile` (effective + persona), `PUT` (declared only — inference is never client-writable).
- `cerebrum_core/engrams/core/mastery_service.py` — PERF wire: `_update_profile_from_perf` called at the end of `recompute_topic_mastery`, the single sink every mastery-affecting path (mcq/flashcard submit, async short/long grading) funnels through. Best-effort (guarded) — profile inference can never break a mastery update.
- `cerebrum_core/learning_center_inator.py` — NOTE-ANALYSIS wire: `_update_profile_from_note_analysis` called from `passive_analysis` + `active_analysis`; resolves the note's owner (`NoteStorage.user_id`) and folds the cached overview's structural signals in. Best-effort (guarded).

**Verified.** Blend math (cold-start→declared conf 0; 20 evidence rows flip a
+0.8 declared to −0.87 conf 0.98; modest evidence partially pulls);
`sanitize_declared` clamp + drop-unknown; storage roundtrip; inference mappers
against the real analysis JSON (1 confused_link → correct pulls) and synthetic
topic mastery; **idempotency** (2 identical note runs = 2 rows, not 4); both
wire paths end-to-end (perf via `_update_profile_from_perf`, note-analysis via
the helper with a stubbed cache); guard no-ops on missing overview. Full-module
import smoke green (94/94).

**Open.**
- LLM enrichment pass — the seam exists (`llm_enrich_note_analysis`,
  `LLM_ENRICH_ENABLED=False`); implement via `models.model_inator` to mine
  free-text `gap_explanation` nuance (e.g. "compresses … rather than rigorous"
  → pattern_detail) that structural signals can't read.
- Finer perf inference — `example_discovery` and precision-vs-connections need
  per-engram dimension scores; today's mapper uses topic-mastery aggregates
  (factual/applied/conceptual/doctoral) and covers abstraction/pattern/depth
  only. Needs an all-engram-masteries accessor.
- Off-profile probing (guard against the teach-to-inferred / measure-via-inferred
  reinforcement loop) is designed but not yet built.
