## 4. Note image upload + serving (stored in the note's own folder)

**What.** Endpoints to upload and serve images that live **inside the note's
folder**: `notes/<note_id>/images/<ulid>.<ext>`.

**Files.**
- `api/routes_bubble.py`
  - `POST /bubbles/{bubble_id}/notes/{filename}/images` (`upload_note_image`) — whitelists png/jpg/jpeg/gif/webp, stores under the note's `images/`, returns a **relative** URL (client prepends its base URL, so the note works regardless of host/port).
  - `GET /bubbles/{bubble_id}/notes/{note_id}/images/{image_name}` (`get_note_image`) — `FileResponse`, path-traversal guarded.
- `api/middleware/daemon_auth_middleware.py` — GET on the image path is **auth-exempt** (`_NOTE_IMAGE_PATH` regex), because `<img>`/`Image.network` can't attach the daemon key/bearer token. Access is capability-based: the image id is an unguessable ULID.

**Note.** Images live in the note dir, so they GC with the note (`rmtree`). The
capability-URL exemption is a deliberate trade-off (flagged for the client's
offline-first pass, where images move to a local cache + stable refs).

**Verified.** `ast.parse` OK on both files; the exemption regex was unit-checked
(matches a valid image URL, rejects `..`/`update`/trailing-slash paths).

## 3. Persist a note's `bubble_id` on update (+ Pyright source-root config)

**What.** (1) `update_note` now writes the note's `bubble_id` (and `note_id`)
into the manifest from the authoritative URL path. (2) Added `pyrightconfig.json`.

**Why.** (1) `NoteManifest.bubble_id` defaulted to `""` and was never persisted,
so `NoteOut.bubble_id` came back empty — a client that merged the response lost
its bubble_id and looped on `PUT /bubbles//notes/update/...` (404). Stamping it at
save fixes it at the source, and an already-affected note self-heals on its next
update. (2) With no Pyright config, the `models` package resolved under two roots
(workspace + `src/`), producing phantom "`Note` is not assignable to `Note`"
errors across the file; pinning the execution root to `src/` makes each module
resolve exactly once.

**Files.**
- `api/routes_bubble.py` — `update_note`: `stored_note.manifest.bubble_id = bubble_id` (+ `note_id` when empty) before save.
- `pyrightconfig.json` (NEW) — `include` + `executionEnvironments` root `src`, venv `src/.env`.

**Verified.** `ast.parse` OK; `pyrightconfig.json` is valid JSON.

## 2. Durable block ids for tap-a-block analysis (+ fix unreachable `/fetch/analysis/full`)

**What.** Two fixes so a note's analysis maps back to specific blocks reliably:
(1) the `/fetch/analysis/full` endpoint is reachable again and actually stamps
`source_block_ids` + `page_id` onto each cached chunk; (2) block identity no
longer falls back to a fragile positional `blk{i}` — an id-less block now gets a
**content-addressed** id.

**Why.** The client was seeing the "old" analysis shape with empty
`source_block_ids`. Root cause was a **misplaced route decorator**: an extracted
`_attach_block_refs` helper landed directly under
`@router_learn.get("/fetch/analysis/full")`, so the route bound to the helper
(which mutates a list in place and returns `None` → endpoint responded `null`),
while the real assembler `get_full_cached_analysis` was left **undecorated and
unreachable**. Separately, even when served, block ids were positional indices
(`blk{i}`), which shift on any insert/reorder and are swapped wholesale on every
page-blob LWW sync — so no stored `source_block_ids` stayed valid.

**Files.**
- `api/routes_learning_center.py` — moved `@router_learn.get("/fetch/analysis/full")` off `_attach_block_refs` (now a plain helper) back onto `get_full_cached_analysis`. Verified via AST that the three `/fetch/analysis*` routes bind to the intended functions.
- `notes/note_util_inator.py`
  - `flatten_blocks` — id resolution is now best→worst: **(1)** client-persisted `block["id"]` (the AppFlowy node id, stable across edits/reorders/sync); **(2)** content-addressed `blk_<sha1(type+text)[:12]>` with an occurrence counter for duplicate blocks (survives reorder; only changes when the block's content changes — exactly when its old analysis is stale anyway); **(3)** positional only as a last-resort tiebreaker, never the identity alone. Logs a WARNING counting id-less blocks so the degraded path is visible during the client migration.
  - added `import hashlib`.

**Verified.** `flatten_blocks` unit check: a real client id passes through, id-less
blocks get stable content-hash ids, two identical blocks disambiguate
(`…_0`/`…_1`), and the degraded-path warning fires. `notes.note_util_inator` and
`api.routes_learning_center` import cleanly.

**Note.** Full durability needs the client to persist AppFlowy node ids (done in
the Flutter repo's matching change-set); until a given note has been re-saved by
that client, the content-hash fallback keeps mapping stable rather than
index-fragile. The registry self-heals: `register_chunk_blocks` replaces a note's
chunk↔block rows on every re-chunk, so each analysis run re-anchors to current ids.

## 1. Fix concurrent-write corruption of note manifests

**What.** Note file writes now use a **unique** temp file per writer (was a shared
`<name>.tmp`), and the note-manifest / page-content reads **degrade gracefully**
on a corrupt file instead of crashing the request.

**Why.** Opening a bubble crashed with `json.JSONDecodeError: Extra data` while
listing notes. Two code paths write the same `notes/<id>/manifest.json` —
`_save_note` (client sync) and `write_note_overview` (analysis pipeline) — and both
went through one shared `manifest.json.tmp`. When they raced (exactly what opening
a bubble triggers: analysis runs while the note syncs), they truncated and wrote
the *same* temp; the shorter payload overwrote the head while the longer one's tail
survived, and the atomic `os.replace` could move that mixed file into place → a
complete JSON object followed by leftover bytes ("Extra data"), which bricked the
whole bubble listing (one bad note took every note down with it).

**Files.**
- `notes/note_util_inator.py`
  - `_atomic_write_text` — unique temp via `tempfile.mkstemp` in the target dir + `flush`/`fsync` + atomic `os.replace`, with cleanup on failure. Each writer gets a private temp, so `os.replace` always moves a whole, well-formed file.
  - `_load_note` — note manifest read now goes through `_safe_read_json` and degrades a corrupt manifest to `{}`; page content is the source of truth in the page folders, so `_ordered_page_ids` rebuilds the note from disk and it still loads (title/overview blank until the next save rewrites clean).
  - `_load_page_folder` — page `content.json` / `manifest.json` reads likewise degrade to defaults rather than 500.
  - added `import tempfile`.

**Verified.** Concurrency repro (8 writers × 4 readers on one file): the **old**
shared-`.tmp` writer produced **575** corrupt reads; the **new** unique-`mkstemp`
writer produced **0**. Module `ast.parse` OK. (A full runtime import here trips an
unrelated `pymupdf`/`libstdc++.so.6` native-load outside the nix devshell — not
related to this change.)

**Note.** Fix stops corruption; `_save_note` and `write_note_overview` still do
independent read-modify-write of the manifest, so a rare concurrent overwrite can
drop a just-merged `overview` (lost update, not corruption) — a per-note write lock
would close that if wanted. The already-corrupted note on disk self-heals on its
next save.
